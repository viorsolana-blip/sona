What works today.

Sona connects Solana wallets, verifies Raydium CPMM Fee Keys, stores authenticated listings and builds an atomic exchange signed by both buyer and seller.

Public implementation. Runtime and source availability verified.

The public Cloudflare Workers/D1 service has been checked with anonymous requests, a fresh wallet’s authentication signature, replay and origin rejection, session invalidation and current Raydium account reads. Atomic settlement has separately executed on an isolated Solana validator. No Sona mainnet sale or independent security audit is claimed.

The exchange

A seller lists a verified Fee Key at a fixed SOL price. A buyer requests the purchase. The seller signs a short-lived transaction, then the buyer reviews and signs the same transaction. It creates the buyer’s token account if needed, transfers exactly one Fee Key and pays the seller. All instruction effects succeed together or roll back together; transaction fees may still apply.

Listings and requests are hosted by Sona. Assets stay in the parties’ wallets until settlement. There is no Sona custody or new escrow program to deploy. Seller approval is required for each buyer, and an approval already released cannot be revoked by merely canceling a listing.

Verify a Fee Key

Read current Solana account state without connecting a wallet. This checks the mint, current holder, canonical Raydium lock, pool, LP escrow and vaults. It does not list an asset or authorize a transaction.

Paste the Fee Key’s token account from your wallet or a Solana explorer to avoid a network-wide holder lookup. This is the token account, not your wallet address. Its mint, balance and owner are still verified on chain.

The prefilled address is an unrelated third party’s Fee Key used for read compatibility. Its recorded holder is a program address, unsupported by Sona’s signing flow. It is not a Sona listing, customer or sale; the current holder may change.

Scope and costs

The current integration transfers an entire CPMM Fee Key held by an ordinary signing wallet. Program-owned and multisig-held keys are not supported by this signing flow. It does not support CLMM positions, partial rights, LP redemption, fee claiming, new liquidity locks or confidential settlement. Public RPC can throttle; read failures are shown instead of fabricated holdings.

No paid RPC key is required. Listing does not require a deposit. A real purchase still costs Solana network fees and, when needed, buyer token-account rent. Hosted operation is subject to platform and public RPC limits; an independent security review remains outstanding.

The same source and evidence are available to every visitor. Recorded local execution, read-only mainnet verification and a completed mainnet marketplace sale are different claims. This page is not a score guarantee or security certification.
